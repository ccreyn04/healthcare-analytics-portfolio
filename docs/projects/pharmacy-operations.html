Pharmacy Operations Dashboard

An operational-performance case study measuring medication turnaround, on-time reliability, priority queues, location variation, and workflow exceptions.

Business question

Where are medication-order turnaround and on-time performance strong, and where should pharmacy leadership investigate workflow bottlenecks?

Project evidence

  • 1,200 synthetic medication orders across five care locations.
  • Interactive filters for location, priority, medication, and controlled-substance status.
  • KPIs for turnaround, on-time rate, STAT reliability, late volume, and long-running orders.
  • Searchable order evidence and PostgreSQL query pack.

Case study narrative

What the analysis demonstrates

Methodology

  1. Defined operational and financial KPIs before analysis.
  2. Validated required fields, status values, date ranges, and numeric columns.
  3. Segmented performance by the business dimensions most likely to guide action.
  4. Separated volume, rate, financial impact, and aging so priorities were not based on counts alone.
  5. Translated findings into a measurable operational recommendation.

Key findings

  • Overall on-time performance is 92.1% with an average turnaround of 57.5 minutes.
  • STAT orders achieve 94.8% on-time performance.
  • Scheduled orders have the weakest on-time rate at 80.2%, indicating that queue rules or batch timing deserve review.
  • Women & Children has the lowest location-level on-time rate in the full sample, while Outpatient Infusion performs best.

Recommendations

  • Create a daily late-order exception report segmented by location, priority, and medication.
  • Review scheduled-order batching, due-time logic, and staffing overlap before changing STAT workflows.
  • Use a standardized turnaround definition and separate order-entry delay from pharmacy processing time in production.
  • Set location-specific targets and require documented root causes for recurring exceptions.

Limitations and next steps

  • The data is synthetic and does not include patient, provider, contract, staffing, or clinical-acuity details.
  • Estimated financial impact uses allowed or simulated savings amounts; it is not a guaranteed recovery value.
  • A production implementation should add data-quality checks, security controls, scheduled refreshes, ownership, targets, and validated business definitions.
  • The next build would connect the same logic to governed source systems and a production BI semantic model.
